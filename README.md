# Velvet Scroll Wedding

GOAL: Build a wedding website from scratch with the following structure. 

Use a blush pink / ivory pastel color palette as the base theme throughout.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. VELVET SCROLL — OPENING MECHANIC (reference image attached: closed roll)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- On first load, show ONLY the rolled-up velvet scroll, centered on screen, 

  tied shut with a golden thread/tassel — exactly like the reference image.

- On tap/click, the scroll should gently unfurl: the top half rises/unrolls 

  upward and the bottom half unrolls downward (reference image: opened roll), 

  revealing a handmade-paper-textured surface in between.

- Once opened, this handmade-paper scroll becomes the persistent background 

  for the ENTIRE site. The golden rods of the scroll should remain visible 

  and pinned at the very top and very bottom of the viewport at all times.

- All site content (every page/section below) loads and lives INSIDE this 

  opened scroll. All scrolling happens within the paper area between the 

  two golden rods — the rods themselves stay fixed, framing the content 

  like a physical scroll being read.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. PAGE ORDER (all inside the scroll)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Page 1 — Ganesha invocation

  - A Ganesha murti illustration, with the "Vakratunda Mahakaya..." shloka 

    written in full beneath/beside it.

Page 2 — Couple names

  - A dedicated page displaying the couple's names as the central content: 

    "Shreya weds Prabhav." Style this as an elegant, centered title 

    treatment (names + "weds" connector), sized as the page's hero content 

    — not a small text line.

Page 3 — Wedding timeline (reference image attached: blue semi-circle timeline)

  - Recreate this same semi-circle timeline LAYOUT, but re-skinned in our 

    blush pink / ivory pastel palette instead of the reference's blue.

  - Each event on the timeline gets its own small illustrative icon/scene 

    relevant to that event (new artwork, matching the palette).

  - Timeline content, grouped by date:

      11th December: Mehandi – 2PM | Engagement & Sangeet – 6:30PM | 

                      Masquerade – 10:30PM

      12th December: Haldi – 10:30AM | Baarat – 4PM | Varmala – 5:30PM | 

                      Fera – 11PM

Pages 4+ — One dedicated page per event, in the order listed above, each 

  containing a full-scene illustration (wide scenic view, not zoomed into 

  the people — figures should read small against a large backdrop of the 

  venue/scenery) plus the event name and time. Do NOT add any small 

  handmade-paper decorative element at the top of these pages.

Per-event theme/venue for the illustrations:

  - Mehandi: dark pink & orange decor, lawn setting with palm trees

  - Engagement & Sangeet: royal blue & gold decor, lawn with a stage and 

    truss lighting

  - Masquerade: black & magenta decor, indoor hall, include a disco ball

  - Haldi: pastel lilac & yellow decor, pool deck setting with rain dance

  - Baarat: people dancing with dhol players (baarat procession scene)

  - Varmala: white & pink decor mandap, set on the beach

  - Fera: "taaron ki chhaon" (under a starry sky) theme, red-toned decor

NOTE: A follow-up prompt is coming with a detailed spec for HOW to build 

these event-page illustrations (format + required animated elements). 

Please hold off on generating final illustrations for pages 4+ until that 

follow-up arrives — it will specify SVG format with animated elements.

4. GENERAL

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- Maintain the blush pink / ivory pastel theme as the connective thread 

  across the timeline and every event page, even as each event has its 

  own accent colors per above.

- Everything (Ganesha page → names page → timeline → event pages) should 

  load and scroll as one continuous experience inside the opened scroll, 

  not as separate disconnected sections.
